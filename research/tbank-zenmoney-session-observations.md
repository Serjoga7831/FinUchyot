# Как современный ZenMoney подключается к личному Т‑Банку

**Дата исследования:** 13 августа 2026 года  
**Ограничение:** исходный код ZenMoney не рассматривался. Выводы основаны на публичной справке ZenMoney и Т‑Банка, а также на пользовательском наблюдении интерфейса.

## Краткий вывод

Современное подключение наиболее обоснованно описывать как **локальное подключение к интернет-банку с отдельной банковской авторизационной сессией**:

```text
номер телефона
  → одноразовое подтверждение SMS/PUSH
  → отдельная сессия в Т‑Банке
  → сессионные данные сохраняются зашифрованно на телефоне
  → ZenMoney с этого телефона периодически читает счета и операции
```

Это не серверный агрегатор ZenMoney и не обычный импорт выписки. Публичные документы не доказывают, что используется официальный партнёрский API для личных счетов, T‑ID или эмуляция именно мобильного клиента. Точный транспорт и формат сессионного секрета не раскрыты.

## Подтверждённые факты

1. ZenMoney поддерживает «подключение к банкам из приложения». Оно работает только на телефоне, где создано; с другого телефона такое подключение запускать нельзя.[1][2]
2. ZenMoney заявляет, что регистрационные данные хранятся зашифрованно на телефоне, не передаются на серверы ZenMoney, а синхронизация идёт напрямую с телефона в банк.[1][5]
3. Для подключения Тинькофф/Т‑Банка публичная справка описывает код авторизации приложения, доставляемый по SMS или PUSH.[4]
4. При последующих синхронизациях загружаются данные с даты прошлой синхронизации и повторно последняя неделя для отслеживания отложенной авторизации.[4]
5. При удалении приложения, выходе из профиля или смене ключа шифрования локальные данные подключения удаляются.[1][5]
6. Т‑Банк использует стандартную модель входа с номером телефона и одноразовым кодом и позволяет управлять активными банковскими сессиями/устройствами.[6][7]
7. Пользователь фактически наблюдал: после подтверждения подключения ZenMoney в официальном приложении Т‑Банка появилась отдельная сессия. Это наблюдение хорошо согласуется с регистрацией отдельного банковского клиента или устройства, но само по себе не раскрывает API.

## Что можно вывести архитектурно

Наиболее вероятная последовательность:

1. ZenMoney с телефона инициирует банковскую авторизацию.
2. Т‑Банк идентифицирует клиента по номеру телефона.
3. Банк направляет одноразовое подтверждение по SMS/PUSH.
4. После подтверждения банк создаёт отдельный авторизационный контекст, видимый пользователю как активная сессия.
5. Сессионный секрет хранится локально в защищённом хранилище телефона.
6. Последующие синхронизации используют сессию без повторного ввода кода, пока банк считает её действующей.
7. При отзыве или истечении сессии потребуется новая авторизация.

Публично неизвестно, является секрет session cookie, access/refresh token, связкой device ID + token или другой внутренней конструкцией.

## Партнёрский API, T‑ID или банковская сессия

### Отдельная банковская сессия — наиболее сильный вывод

На это указывают:

- локальность подключения;
- подтверждение банковским одноразовым кодом;
- появление отдельной активной сессии в Т‑Банке;
- невозможность запустить подключение с другого телефона;
- повторная синхронизация с сохранёнными локальными данными.

### Партнёрский API — не подтверждён и не исключён

Т‑Банк включает ZenMoney в каталог готовых интеграций, однако публичная страница не раскрывает, относится ли это к личным счетам и какой механизм используется мобильным ZenMoney.[8]

Возможны две модели:

- ZenMoney является зарегистрированным партнёрским клиентом и получает специальный идентификатор/политику доступа;
- ZenMoney использует разрешённый клиентский механизм интернет-банка без публичной документации.

Появление обычной банковской сессии возможно в обоих случаях.

### T‑ID — маловероятное объяснение

T‑ID обычно является потоком входа на сайт или в приложение партнёра с отдельным экраном согласия на передачу профиля. Публичное описание ZenMoney говорит о банковском подключении, локальных регистрационных данных и прямой синхронизации с банком, а не о T‑ID.[1][9]

### «Эмуляция мобильного приложения» — не доказано

По публичным документам нельзя определить транспорт:

- внутренний mobile API;
- web API;
- встроенный браузер;
- специальный партнёрский адаптер;
- другой клиентский интерфейс.

Поэтому корректная формулировка: **локальный банковский коннектор с отдельной сессией**, а не «точная копия родного приложения».

## Пароль, PIN и срок жизни

Публичная инструкция не фиксирует полный набор факторов именно для текущего ZenMoney → личный Т‑Банк. Пользователь наблюдал номер телефона и одноразовый код; нельзя без дополнительного подтверждения утверждать, что пароль или PIN никогда не требуются.

Точный TTL сессии не опубликован. Подтверждено только, что локальные данные живут, пока их не удалили и банк не потребовал повторную авторизацию. Если дополнительный код требуется при каждой синхронизации, ZenMoney предупреждает, что постоянная фоновая работа невозможна: остаётся ручной запуск или режим раз в день.[3]

## Значение для FinUchyot

Технический способ автоматической синхронизации личного Т‑Банка существует. Неизвестна не возможность, а **публичный контракт подключения**.

Т‑Банку следует направить конкретный запрос:

> Предоставляет ли Т‑Банк сторонним приложениям персонального финансового учёта механизм регистрации отдельной клиентской сессии с подтверждением номера телефона одноразовым кодом и доступом только на чтение счетов, балансов и истории операций?

Нужно выяснить:

- нужен ли партнёрский договор;
- выдаётся ли client ID;
- есть ли read-only scope;
- разрешена ли фоновая синхронизация;
- где разрешено хранить сессионный секрет;
- как пользователь отзывает подключение;
- есть ли SDK/sandbox/закрытая документация;
- может ли всё выполняться локально без передачи банковских данных на сервер FinUchyot.

До ответа банка воспроизведение закрытого протокола остаётся неофициальным и нестабильным вариантом.
